# 安全方案：敏感级路由与内网私有化部署

对应实现：`serving/router.py`、`serving/api.py`、`deploy/`。

## 1. 威胁模型

律所场景的核心风险不是「被黑客攻击」，而是**内部数据误外发**：
律师把含当事人信息的案卷内容粘进提问框，若系统把它发给公网
模型 API，即构成客户保密义务违约。因此安全设计的第一原则：

> **涉案情数据在架构上不可能触达外网，而不是靠提示词约束模型。**

## 2. 数据敏感级（三级）

定义于 `corpus/schema.py::Sensitivity`，随块级元数据全链路传递：

| 级别 | 含义 | 允许去向 |
|---|---|---|
| `public` | 公开法规、普法知识 | 本地 7B 或云端（脱敏后） |
| `internal` | 所内模板、办案指引 | 仅内网 |
| `case` | 案卷、当事人材料 | 仅内网，且仅本地模型 |

## 3. 敏感级路由（`serving/router.py`）

生成请求下发前，路由层做三重判定：

1. **查询侧信号检测**：命中案号、当事人称谓、文书名称、标的金额
   等涉案情模式 → 无条件本地 7B；
2. **检索侧敏感级**：本次召回的知识块含 internal/case → 本地 7B；
3. **PII 掩码后放行**：仅当上述两项均干净且显式配置了云端通道，
   手机号/身份证/银行卡/固话完成掩码后才允许走云端。

判定顺序是「宁可误拦、不可误放」：任何一层命中即锁定本地，
云端是白名单例外而非默认。

## 4. RBAC 与越权审计（`serving/api.py`）

- 角色 → 可见敏感级：合伙人/执业律师（全部）、律师助理
  （公开+内部）、客户门户（仅公开）；
- 检索命中超出角色可见级的块**静默过滤**并写审计事件
  `sensitivity_denied`（记录 token 摘要、角色、被过滤数量与
  查询长度，不落敏感原文）；
- 令牌桶限流（默认 10 req/s），触发限流同样留痕；
- 审计日志 JSONL 追加写，可对接所内 SIEM。

## 5. 拒答即安全能力

`verify/citation_checker.py` 的回查逻辑同时是安全闸门：
引用对不上现行有效知识库 → 澄清或拒答。废止条文在语料层
被检索过滤、在微调层被训练为拒答样本、在校验层被回查拦截——
同一风险在三个层面各有一道独立防线。

## 6. 内网部署要点（详见 `deploy/README.md`）

- 全部服务（API/Milvus/MySQL/Redis/vLLM）仅监听内网段，
  不出站访问公网；
- 模型权重经安全审查后以离线介质带入，镜像构建在断网环境完成；
- `.env` 中的密钥仅允许占位符入库，真实值经所内密钥管理下发；
- 备份策略：Milvus 快照 + MySQL 主从 + 案卷原文三副本，
  备份介质同属内网保密资产。
