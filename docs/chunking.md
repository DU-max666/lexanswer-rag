# 切分设计：按文档类型路由的四套切分器

对应实现：`corpus/splitters.py`，元数据契约见 `corpus/schema.py`。

## 为什么不能“一把梭”固定窗口切分

法律语料的四种典型文本，语义单元完全不同：

| 文档类型 | 天然语义单元 | 固定窗口的后果 |
|---|---|---|
| 法规 | 条（含款、项） | 一条被拦腰截断，引用编号丢失 |
| 附表 | 行（依赖表头） | 行脱离表头后“200元”“一只”不可解 |
| 类案 | 争点段落 | 事实段与说理段混在一起，检索噪声大 |
| 咨询记录 | 问答轮次 | 只留提问缺答案，只留答案缺语境 |

因此 `split_document()` 先按元数据/正文特征路由（`detect_doc_type`），
再进入对应切分器。

## 1. 法规：章/节/条/款 父子块

**结构规则**（`RegulationSplitter`）：

- `第X章` / `第X节` → 独立低优先级块，仅作章节过滤上下文；
- `第N条` → **父块**，正文自带引头 `《法名》第N条`，条号同时以
  整数写入 `article_no` 字段（供引用回查精确比对）；
- `（一）（二）…` → **子块**，`parent_id` 指向所属条父块。

**为什么要父子两层**：款/项子块粒度细、向量表征精准，适合召回；
但生成时只给子块会让模型缺语境。检索命中子块后由
`retrieval/parent_child.py` 回溯父块，**整条注入**提示词，并在证据
尾部标注「用户问题命中的款项」。

**中文条号归一**：`第二十三条` 与 `第23条` 统一解析为整数 23
（`cn_to_int`），引头展示仍用中文数字，符合法律文本惯例。

## 2. 附表：按行切、每行带表头

`【附表 表名】…【完】` 块内，首行为表头，其余为数据行。
每行生成子块，文本拼装为 `列名=值；列名=值`：

```
附表《危险犬只名录（节选）》: 品种=藏獒；体型标准=成年肩高超过七十六厘米；管理措施=重点管理区禁止饲养
```

父块为整表（表头 + 全量行），命中任意行可回溯整表注入。
这样「藏獒能不能养」这类问题能命中单行，而「名录里有哪些品种」
回溯整表后模型能完整作答。

## 3. 类案：语义断崖切分

`CaseSplitter` 以段落为原子单位，计算相邻段落的语义相似度，
在相似度**骤降处（断崖）**断开：同一争点内的段落粘连成块，
争点切换处果断切开。

- 生产路径：BGE-M3 稠密向量相邻段余弦相似度，阈值约 0.35；
- 离线降级：字符二元组 Jaccard（接口一致，阈值 0.18），
  无模型也能保持切分行为稳定；
- 过短残段（<40 字）丢弃，避免噪声块污染召回。

## 4. 咨询记录：按轮次成对切分

`ConsultSplitter` 识别 `咨询人：/律师：`（或 `用户：/法务：`）轮次
标记，一问一答**成对**合并为一个块。只切单边会破坏 FAQ 短路与
类案检索所需的完整交互语境。

## 去重与效力状态（`corpus/dedup.py`）

同一 `(法名, 条号, 块类型, 款号)` 多版本并存时：

1. 效力优先：现行有效 > 已修订 > 草案 > 已废止；
2. 同效力比版本（约定版本号为公布日期串）；
3. **废止块不删除**，移入负样本池——微调拒答能力依赖它。

父块被替换时其 `child_ids` 自动重算，保证指针不悬空。
