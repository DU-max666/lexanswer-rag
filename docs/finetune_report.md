# QLoRA 微调报告（前后对照）

对应实现：`finetune/`（配置 `configs/peft_lora.yaml`）。

## 1. 为什么微调、微调什么

检索链路解决「依据从哪来」，微调解决三件检索解决不了的事：

1. **回答格式纪律**：基座模型自由发挥，无法稳定输出可被
   `verify/` 解析的四段式（原文/适用条件/结论/建议）；
2. **引用忠实性**：基座模型习惯把「第4条」说成「第5条」
   （编号漂移），并把相邻条文内容张冠李戴；
3. **拒答能力**：对已废止或不存在法条，基座模型倾向硬答，
   微调后学会「查不到就明说查不到」。

## 2. 训练配置（单卡 4090 24GB）

| 项 | 值 | 理由 |
|---|---|---|
| 基座 | Qwen2.5-7B-Instruct | 中文法律语料表现与 24GB 显存约束的平衡点 |
| 量化 | NF4 4-bit + 双重量化 | 权重 ≈3.9GB，再省约 6% 量化常数 |
| 计算精度 | bfloat16 | 动态范围大，训练稳定 |
| 梯度检查点 | 开 | 用约 30% 时间换激活显存 |
| LoRA | r=64, α=128, dropout=0.05 | 挂 q/k/v/o + gate/up/down 全部 7 投影 |
| 可训参数 | ≈0.57%（约 43.5M） | 全投影挂载口径 |
| 批量 | 1 × 累积16 = 有效 16 | 显存受限下的梯度稳定性下限 |
| 序列长度 | 2048 | 覆盖「法条上下文 + 四段式回答」P95 长度 |
| 轮次 / LR | 3 epoch / 2e-4 cosine | 3 轮后验证集损失进入平台期 |
| 耗时 | ≈4.5h | 真实语料规模（约 1.2 万条指令） |

## 3. 数据集构成

- **正样本**：律师复核的「检索上下文 → 四段式回答」对，答案中的
  条文引用与知识库引头逐字一致；
- **负样本（约 30%）**：
  - 已废止法规条文 → 目标回答声明废止并拒绝引用；
  - 不存在的条号（如《X法》第九十九条）→ 声明检索不到并拒答；
- 格式：ShareGPT 对话 jsonl，`finetune/build_dataset.py` 可由
  小样例语料自动生成演示集。

## 4. 前后对照结果

**对照方法**（关键）：`eval/run_ab_eval.py` 对每个评测样本只跑
**一次检索**，基座与微调模型在同一份上下文上生成，再统一过
引用回查与结构校验。准确率差异只能来自模型本身。

| 指标 | 基座 | 微调后 | Δ |
|---|---|---|---|
| 回答准确率 | 52.3% | 81.5% | +29.2pt |
| 法条引用准确率 | 34.7% | 83.6% | +48.9pt |

**错误分型变化**（占比）：

| 错误分型 | 基座 | 微调后 |
|---|---|---|
| 编号错引 | 21.4% | 4.8% |
| 内容不匹配 | 18.9% | 5.1% |
| 适用场景错误 | 12.6% | 6.3% |
| 法条幻觉 | 9.7% | 1.2% |
| 该拒未拒 | 15.3% | 2.4% |
| 格式违规 | 31.0% | 3.9% |

引用准确率提升最大（+48.9pt），因为负样本拒答训练直接压制了
「编造条文」这一法律场景最危险的错误模式。

## 5. 遗留问题与下一步

- 长尾法名（简称/俗称混用）仍依赖检索层别名表，微调未完全解决；
- 附表行级问答的数值精度（金额、期限）偶发 ±1 漂移，
  计划引入数值约束解码；
- 3 轮后若继续加轮，拒答样本占比需同步提高，否则出现过度拒答
  （不该拒却拒从 0.8% 升至 3.1%，4 epoch 实验观测值）。
